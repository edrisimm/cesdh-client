The ScenarioMarie suspects costs are 15% too low

After Part 1, the groupe-e-planning-process repository holds 59 datasets on main with complete PROV-O lineage from raw inputs to publication figures.

Marie wants to explore a sensitivity scenario: what if expansion costs are 15% higher than projected? She needs to revise the costs dataset without disturbing the published baseline.

Three actions, one outcome

Branch — create a safe workspace.
Revise — upload modified costs with lineage.
Audit — compare both branches, trace provenance.

Phase 7Verify Part 1 state and create the branch

The script confirms the Part 1 repository exists, switches identity to Marie, searches for the target dataset, and creates a new branch.

  • 1Identity — switches to marie / Marie Dupont. All Part 2 provenance records are attributed to her.
  • 2Search — finds the costs dataset on main to use as the revision target.
  • 3Branch — creates sensitivity-2025 from main. This inherits all 59 datasets without copying files.

If the repository is missing, the script aborts with a clear error — it never recreates Part 1's state.

Phase 8Download the costs dataset

The script searches for expansion_costs, then downloads the matching dataset to a local working directory.

  • 1Search — cesdh.search("expansion_costs") finds the dataset by name.
  • 2Download — cesdh.download_to_file() streams the file to ./part2_workdir/.
  • 3Modify — loads the file into a DataFrame, multiplies all numeric columns by ×1.15.

Why download first?

Marie revises actual data from the hub — not a separate local copy. This ensures the revision is based on exactly what was published.

Phase 8Upload the revision with lineage

The modified costs file is uploaded to the sensitivity-2025 branch with a derived_from link back to the original dataset.

  • 1Branch — the upload targets sensitivity-2025, not main. The baseline is never touched.
  • 2derived_from — points to the original costs dataset. This creates a PROV-O lineage edge from revision to original.
  • 3run_id — sensitivity_rerun_2025 groups this upload under a named activity.

This is the same upload() call used throughout Part 1 — only the branch and lineage arguments differ.

1. Safe what-if exploration

The revised dataset is linked to the original via PROV-O. The full chain is queryable from revision to raw input, across branches.

3. Multi-user attribution

Two researchers, two branches, two content hashes. The hub records who changed what without manual bookkeeping.
